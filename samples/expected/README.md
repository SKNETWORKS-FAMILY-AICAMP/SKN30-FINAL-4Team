# 목업 기대 결과

목업 hwpx 는 입력 문서이고, 이 디렉터리가 정답지다. 둘을 분리한 이유는
정답이 입력 안에 있으면 모델이 추론으로 맞혔는지 문서에 적힌 답을 읽었는지
구분할 수 없기 때문이다. 2026-08-29 이전 목업에는 다음 같은 문장이
본문에 있었고, 전부 걷어냈다.

```
※ [치명적 충돌: FIT-5 CONFLICT] 업력 3년 미만 초기 창업기업에게
   3개년 연평균 매출 50억원을 요구하여 정면 모순 발생!
```

결함 자체는 그대로 두었다. 제목의 등급·정합도 표기와 `-> FIT-6 INFO_LACKING
발생` 같은 꼬리표만 제거했고, 공란 표기는 `(공란)`, `(미기재)`, 값이 비어
있는 라벨, `해당없음` 으로 나누어 부재 표현이 한 가지만 시험되지 않게 했다.

## 필드

- `document`: 대상 hwpx 경로
- `grade`, `source_annotation`: 원래 제목에 있던 등급 표기. 우리 FIT 점수와
  같은 척도가 아니므로 목표값이 아니라 출처 기록으로만 쓴다
- `annotated_defects`: 문서에서 걷어낸 주석이 지목하던 결함
- `fit`: 관계별 기대 상태. `covered_by_contract` 가 `false` 이면 결함은
  실재하지만 현재 FIT 관계 7개 계약이 표현할 수 없는 종류다. 채점에서
  실패로 세지 않는다
- `cpl`: 필드별 기대 상태
- `blank_markers`: 그 문서가 쓰는 부재 표기. 표기별 처리 차이를 볼 때 쓴다
