4. 파서가 성공과 실패를 가르는 기준




SUCCESS
텍스트와 블록이 있고 모든 block ID와 위치 정보가 유효하며 warning이 없음.


PARTIAL_SUCCESS
텍스트는 사용할 수 있지만 지원하지 않는 블록이나 확정하지 못한 구조가 있어 warning이 존재.


PARSE FAILED
지원하지 않는 파일, 손상·암호화·위험한 파일, 빈 텍스트/블록, 잘못된 결과 계약.




이번 파일이 PARTIAL인 이유
16셀 중 13셀에서 한 ParagraphBlock 안에 여러 inline run이 있었습니다. 원문과 순서는 보존했지만 그것이 실제 문단 경계라는 근거가 없어 structure_status=unresolved로 기록했습니다.



5. 파싱 결과가 CPL 입력으로 바뀌는 방식




일반 문단은 블록 하나가 fragment가 되고, 표 셀에 여러 segment가 있으면 segment 하나가 fragment가 됩니다. 서버가 다음처럼 고유 근거 ID를 붙입니다.


body:4:cell:3:1:segment:0  → ○ 사업기간 : 2026. 03. 01. ~ ...
body:4:cell:3:1:segment:1  → ○ 사업예산 : 금 1,500,000,000원 ...
body:4:cell:3:1:segment:2  → ○ 지원대상 : 경상북도 소재 ...
body:4:cell:3:1:segment:3  → ○ 지원조건 : 바이오/헬스케어 특허 ...
body:4:cell:3:1:segment:4  → ○ 지원내용 :


따라서 unresolved는 내용을 잃었다는 뜻이 아닙니다. 내용은 CPL에 전달되지만, 파서가 이것을 확정된 문단 구조라고 보증하지 않는다는 뜻입니다.

7. 실제로 어디에서 안 됐는가


① 파서 구조 한계
13개 셀의 inline run이 실제 문단인지 확정하지 못했습니다. 페이지 번호도 제공되지 않았습니다. 다만 원문과 segment는 CPL에 전달됐습니다.


② CPL 의미축 누락
사업목적 원문은 있었지만 LLM이 PURPOSE_SPECIFIC_OBJECTIVE와 PURPOSE_PROBLEM_DOMAIN만 만들고 PURPOSE_DIRECTION, PURPOSE_TARGET_CONDITION을 만들지 못했습니다. 이 때문에 FIT-1~3의 왼쪽 근거가 0건이 됐습니다.


③ CPL evidence grounding 실패
NEW_OR_CHANGED_CONTENT 근거는 REF_NOT_FOUND, 지원대상 근거 1건은 NOT_VERBATIM으로 폐기됐습니다. 원문이 없었던 것이 아니라 LLM이 서버 계약과 맞지 않는 ref/구간을 반환한 문제입니다.


④ Rule 정규화 한계
2026. 03. 01. ~ 2026. 12. 31. (10개월)은 정확히 추출됐지만 현재 기간 정규식이 일 단위 표기를 정규값으로 만들지 못해 VALUE_NOT_SPECIFIC이 됐습니다.


⑤ SIM 응답 계약 실패
Top 5 검색은 성공했지만 LLM이 비교 가능 판정을 반환하면서 양쪽 evidence를 모두 제시하지 않아 Assessable SIM response requires evidence on both sides로 전 후보가 ON_HOLD가 됐습니다.

결론: 이번 파일은 “파일을 읽지 못한 파싱 실패”가 아닙니다. 문자와 표 셀은 보존됐지만 표 내부 문단 구조는 부분 확정 상태이고, 실제 치명적인 손실은 그 다음 CPL 의미축 선택과 LLM evidence 계약에서 발생했습니다. 따라서 파서·CPL Rule·CPL LLM·후단 사전검증을 각각 분리해서 고쳐야 원인을 숨기지 않습니다.
