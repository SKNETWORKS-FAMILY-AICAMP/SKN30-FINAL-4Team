────────────────────────────────────────────────────────
2. 미커밋 변경 — FIT 점수 분모
────────────────────────────────────────────────────────

기존에는 분모가 "판정된 관계"만이었다.

    denominator = sum(100 * weight for r in assessable)

그래서 7개 중 하나만 판정되고 그게 FIT 이면 100점이 나왔다.
근거 범위보다 강한 결론이라 SIM CR-09 와 같은 종류의 문제로 봤다.

분모를 7개 전체로 고정했다.

    denominator = sum(100 * weight for r in relations)

판정 못 한 관계는 0점으로 남는다. 만점이 안 나오는 건 감수하기로 했다.
FIT-4 가 계약상 항상 INSUFFICIENT 라 균등 가중치 기준 14.3점이 영구히
빠지는데, 검토 보조 도구가 "100% 정합"이라고 말하는 것 자체가 과하다는
판단이었다.

예외를 하나 뒀다. 7개 전부 판정 불가면 0.0 이 아니라 None 이다.
"정합도 0%"와 "판정할 근거가 없음"은 다른 말이다.

    value = numerator / denominator * 100 if assessable else None

실측 변화

    문서            이전     지금
    mockup_08       90.0  →  50.0
    우수사례         87.5  →  50.0
    mockup_05        0.0  →   0.0
    mockup_06       None  →  None

버전은 fit_scoring fit-alpha-v0.2 → v0.3,
fit_ruleset_version fit-v0.3 → v0.4 로 올렸다.
프론트 계약(value: number | null 등)은 그대로다. 계산식만 바뀌었다.


────────────────────────────────────────────────────────
3. 변동성 측정 — 같은 문서 8회
────────────────────────────────────────────────────────

FIT 판정 단계를 0/50/100 세 단계에서 더 늘려야 하는지 논의하다가,
먼저 변동성을 재봤다. mockup_08 로 CPL→FIT 만 8회 반복했다.
(SIM·검색·리포트는 건너뛰었다. tmp/fit_variance_eval.py)

FIT 점수

    run 1  50.0    run 5  50.0
    run 2  50.0    run 6  21.4
    run 3  21.4    run 7  50.0
    run 4  35.7    run 8  35.7

    고유값 21.4 / 35.7 / 50.0   폭 28.6점

같은 문서, 같은 코드인데 15단계 척도에서 4단계를 오간다.

관계별 상태 분포

    FIT-1  INSUFFICIENT:8                            안정 (항상 판정 못 함)
    FIT-2  FIT:6  INSUFFICIENT:2                     흔들림
    FIT-3  FIT:6  NEEDS_REVIEW:1  INSUFFICIENT:1     흔들림
    FIT-4  INSUFFICIENT:8                            계약상 고정
    FIT-5  NEEDS_REVIEW:6  FIT:2                     흔들림
    FIT-6  FIT:4  INSUFFICIENT:3  NEEDS_REVIEW:1     흔들림
    FIT-7  INSUFFICIENT:8                            양식상 단측

흔들리는 4개 중 3개는 등급이 아니라 판정 가능 여부 자체가 오간다.
FIT ↔ INSUFFICIENT 는 "정합함"과 "판정 못 함" 사이를 왔다 갔다 하는 것이다.
순수한 등급 흔들림은 FIT-5 하나뿐이다.

상류 CPL 도 같이 흔들린다.

    확인율    10 ~ 11 / 13
    회수율    0.456 ~ 0.570      폭 11%p

그래서 판정 단계를 늘리는 건 지금 하지 않기로 봤다. 3단계도 안정적으로
못 내는 상태에서 5단계를 요구하면 폭만 커진다. 그리고 흔들림의 대부분이
등급 문제가 아니라 판정 가능 여부 문제라 단계를 늘려도 해결되지 않는다.

로그에서 8회 전부 반복된 것

    CPL evidence dropped field=PURPOSE_GOAL         reasons=['FIELD_NOT_ALLOWED']
    CPL evidence dropped field=IMPLEMENTATION_PLAN  reasons=['FIELD_NOT_ALLOWED']

허용되지 않은 축을 매번 붙이려다 거부된다.
FIT-1 이 8회 모두 INSUFFICIENT 인 것과 관련이 있어 보이는데
아직 어떤 축인지는 확인하지 못했다.


────────────────────────────────────────────────────────
4. 회수 격차 분석 — 골든 대비 어디서 잃는가
────────────────────────────────────────────────────────

골든셋 정리를 먼저 했다. 한 단어짜리 인용을 정답에서 뺐다.

    제외  EFFECT_SUBJECT    "참여기업"
    제외  EFFECT_DIRECTION  "강화" / "확대" / "가속"

접지 가치가 없고 문서 여러 곳에 나타나 서버가 모호 인용으로 거부한다.
방향은 EFFECT_CONTENT 의 속성으로 보는 게 맞다고 판단했다.
숫자를 올리려는 게 아니라 잴 수 없는 걸 분모에서 뺀 것이다.

    mockup_08   79건 → 75건
    mockup_03   40건 → 37건

case 431 채점 결과

    필드 상태 일치     12/13
    근거 회수율        47/75  =  62.7%
    정밀도             47/60  =  78.3%
    Rule 정규값 정확도 22/22  = 100%

필드별 회수

    REQUEST_TYPE                4/4      BUSINESS_NEED             3/4
    BUSINESS_PERIOD             1/1      EXPECTED_EFFECTS          7/11
    LEGAL_BASIS                 2/2      PURPOSE_GOAL              3/5
    LINKED_POLICY               3/3      SUPPORT_CONTENT_AND_SCALE 4/11
    BUDGET                      6/6      DELIVERY_SYSTEM           4/13
    TARGET_AND_CONDITIONS       9/10     IMPLEMENTATION_PLAN       1/4
                                         NEW_OR_CHANGED_CONTENT    0/1

상위는 전부 Rule 담당 필드고 아래로 갈수록 LLM 의미 축 비중이 커진다.

못 짝지은 28건을 원인별로 갈랐다. 정보를 아예 못 읽은 건 거의 없고
읽고도 다르게 담은 것이 대부분이다.


원인 1. 한 줄을 한 건으로 뭉친다  (약 15건)

이렇게 나와야
    KPI_NAME         "사업화 성공률"
    KPI_TARGET_VALUE "목표값 30%"
    KPI_BASE_YEAR    "기준연도 2025년"

지금 나오는 것
    KPI_NAME         "사업화 성공률: 목표값 30%, 기준연도 2025년"
    KPI_TARGET_VALUE "사업화 성공률: 목표값 30%, 기준연도 2025년"

같은 줄이 두 축으로 중복 인용된다. 지표가 4개인데 목표값 인용은 2건뿐이라
"목표값 90건", "목표값 15%"가 짝을 찾지 못한다.

지원항목도 같다. 시제품 제작비 / 공인 시험인증비 / 판로개척 마케팅비 셋이
문장 하나의 SUPPORT_ACTIVITY 한 건으로 뭉친다.
보조율 80% 와 자부담률 20% 도 한 줄에 있어 SUBSIDY_RATE 한 건이 되고,
서로 다른 두 비율이 한 근거에 들어가 정규값이 하나만 남는다.


원인 2. 축이 어긋나거나 안 붙는다  (약 9건)

    "1단계(2026~2027년): …"  →  SUBPROGRAM_PLAN_CONTENT   (기대 ANNUAL_PLAN_CONTENT)

연차 계획이 하나도 없다고 판정되어 IMPLEMENTATION_PLAN 이 MISSING 으로
떨어진다. 근거가 3건 남아 있는데도 그렇다. 13필드 중 유일한 상태 불일치다.

여기에 대해서는 앞선 검토에서 "occurrence 가 있으면 MISSING 금지" 라는
제안이 나왔었는데, AGENTS.md 225행이 IMPLEMENTATION_PLAN 은 연차별과
내역사업별을 따로 판정한 뒤 "하나라도 누락이면 MISSING" 으로 정하고 있어
상태 보정은 계약 위반이라는 지적을 받았다. 그 지적이 맞다고 보고
상태가 아니라 축 오분류를 원인으로 본다.

    DELIVERY_STEP_ROLE  →  축이 붙지 않음 (Rule 로만 잡혀 axis_code = None)
    "공고·선정은 부산광역시, 접수·평가·협약·집행은 …, 사후관리는 …"  한 줄에 역할 3건

    COND_COMPANY_TYPE   →  업종 줄에 잘못 붙음
    정작 "「중소기업기본법」 제2조에 따른 중소기업" 줄에는 아무 축도 없다


원인 3. 인용이 너무 넓다  (약 4건)

PURPOSE_GOAL 세 축이 사실상 같은 문장 전체를 가리킨다. 축은 맞게 붙었지만
어디가 대상 한정이고 어디가 방향인지 구분되지 않는다.
PURPOSE_PROBLEM_DOMAIN 은 아예 붙지 않았다.


────────────────────────────────────────────────────────
5. 논의 중인 방향
────────────────────────────────────────────────────────

두 가지를 나눠 보고 있다.


(1) 구간을 좁히는 것 — 프롬프트

현재 CPL 프롬프트는 이렇게 지시한다.

    같은 원문이 여러 축을 지지하면 축별로 반환

모델은 이걸 "줄 전체를 여러 축으로 반복 인용하라"로 읽고 있는 것으로 보인다.
필요한 건 반대다.

    축이 실제로 가리키는 최소 구간만 인용한다

다만 프롬프트 문구 추가의 효과는 확신할 수 없다. 앞선 검토에서
"필요한 지시는 이미 v0.9 에 적혀 있는데 지켜지지 않는 상황이라
문구를 계속 쌓으면 목업 과적합 위험이 크다"는 지적이 있었고 동의한다.
그래서 바꾼 뒤 8회 다시 재서 회수율 폭(현재 45.6~57.0%)이
줄어드는지 확인하는 것까지가 한 묶음이다.


(2) 묶음을 표현하는 것 — Rule 이 계산

occurrence 가 평면이라 "목표값 30%"가 어느 지표의 것인지 표현할 수 없다.
지표 4개의 이름·목표값·기준연도가 서로 연결되지 않는다.

여기에 대해 논의한 것은, 그룹을 LLM 에게 요구하지 말고
코드가 계산하자는 것이다. _evidence_context 가 이미 인용 구간의 위치를
찾고 있어서 몇 번째 줄인지가 바로 나온다.

    - 사업화 성공률: 목표값 30%, 기준연도 2025년   ← line 3
    - 신규 고용창출: 목표값 240명                  ← line 4

    KPI_NAME         "사업화 성공률"    group = ...#3
    KPI_TARGET_VALUE "목표값 30%"       group = ...#3
    KPI_NAME         "신규 고용창출"     group = ...#4

줄 번호는 닫힌 사실이라 판단이 필요 없고 같은 문서면 항상 같은 값이 나온다.
축 하나도 안정적으로 못 붙이는 상태에서 LLM 에게 group_id 를 요구하면
실패 지점만 늘어난다고 봤다.

프론트 영향은 additive 라 크지 않을 것으로 본다. source_locator 에
이미 paragraph_index 가 있어서 line_index 를 얹는 형태면
새 최상위 필드도 필요 없다.

중요한 점은 (2)만 해서는 회수율이 오르지 않는다는 것이다.
지금처럼 줄 전체를 인용하면 두 축이 같은 그룹에 들어갈 뿐
"목표값 90건"은 여전히 안 나온다.
(1)이 회수율을 올리고 (2)가 그것을 쓸모 있게 만드는 관계다.

그래서 순서는 (1) → 8회 재측정 → (2) 로 보고 있다.
그래야 변화가 프롬프트 덕인지 그룹 덕인지 갈린다.


판정 단계 세분화(0/50/100 을 더 나누는 것)는 보류하기로 했다.
3절의 변동성 결과가 근거다.


────────────────────────────────────────────────────────
6. 아직 손대지 않은 것
────────────────────────────────────────────────────────

앞선 잔여문제 정리에서 나왔는데 아직 안 고친 것들이다.

기간 파서 — 무효 날짜에서 종료일이 시작일로 승격된다

    _normalize_period("2026. 02. 30. ~ 2028. 12. 31.")
      → {'start': '2028-12-31', 'end': None, 'single_year': True}

    2월 30일이 무효라 버려지는 것까지는 맞는데, 종료일이 시작일 자리로
    올라가 3년 사업이 단년도로 기록된다. 실패가 아니라 틀린 값을 저장한다.
    정상 표기 7종은 모두 통과한다.

법령 fallback 이 한정어를 법령명으로 만든다

    _legal_citations("관련 법령에 따라 추진")
      → [('관련 법', {'law_name': '관련 법', 'article': None})]

    판별기준 8.2 는 이걸 "근거 언급은 있으나 특정 불가"로 두라고 한다.
    지금은 거짓 PRESENT 가 된다. 복수 법령·조문 추출 자체는 정상이다.

라벨 포함 여부만 다른 중복 occurrence

    DELIVERY_METHOD_TYPE  "시 출연기관 위탁(보조)"
    DELIVERY_METHOD_TYPE  "수행방식: 시 출연기관 위탁(보조)"

    무조건 긴 쪽을 남기는 방식은 최소 충분 Evidence 원칙과 Rule
    중복제거 우선순위에 어긋난다는 지적이 있었다. 동일 위치·축·role·
    정규값까지 같은 경우로 제한하는 방향으로 보고 있다.

test_retrieval 격리 — 1절 참고

계약 공백 — 사업목적의 정량 표현, 성과지표의 측정시점을 담을 축이 없다.
FIT-7 은 실제 양식이 지원규모를 별도 구역으로 두지 않아 항상 단측이 된다.
이건 CPL 수정으로 우회하지 않고 별도 계약 논의로 두기로 했다.
