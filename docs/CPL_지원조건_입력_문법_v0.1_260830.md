# CPL 지원조건 입력 문법 v0.1

- 버전: `cpl-condition-input-v0.1`
- 결정일: 2026-08-30
- 상태: 이번 Slice 6 보완의 구현 계약
- 대상 필드: `TARGET_AND_CONDITIONS` 중 `source_role=CONDITION`

## 1. 근거와 목적

이 문법은 다음 원문과 최신 계약을 구현 가능한 닫힌 입력 경계로 구체화한다.

- `중소기업지원사업_PreReview_CPL_판별기준_정리본_20260821.md` §11.2
- `docs/Pre-review_CPL_FIT_SIM_계약_정정기록_v0.1_260829.md` CR-01, CR-04
- 프로젝트 `AGENTS.md`의 CPL Slice 6 정정 계약

지원조건 하위 라벨은 의미를 추측하는 키워드가 아니라 문서 작성자가 값의 축을
명시하는 서식이다. 서버는 알려진 라벨과 그 값 범위만 Rule로 구조화하고, 라벨이
없는 열린 의미는 이 문법을 근거로 추론하지 않는다.

## 2. 지원하는 입력 형태

지원조건 영역의 한 줄은 다음 형식을 지원한다.

```text
[선택적 글머리·공백] 알려진 라벨 [공백] (":" | "：") [공백] 값
```

한 줄에 알려진 라벨이 둘 이상이면 쉼표(`,`), 가운데점(`·`) 또는 대시 글머리
뒤에 다음 라벨을 이어 쓸 수 있다.

```text
- 지역: 대전광역시, 업종: 제조업
```

라벨 안의 공백은 선택적이다. 예를 들어 `종사자 수`와 `종사자수`는 같은
라벨로 본다. 긴 라벨은 짧은 별칭보다 먼저 일치시킨다.

## 3. 알려진 라벨과 축

§11.2의 라벨을 다음 축에 대응한다. 별칭은 같은 행의 축과 값 범위 계약을
공유한다.

| 기준 라벨 | 허용 별칭 | `axis_code` |
|---|---|---|
| 지역 | 소재지 | `COND_REGION` |
| 업종 | 없음 | `COND_INDUSTRY` |
| 업력 | 없음 | `COND_BUSINESS_AGE` |
| 매출액 | 없음 | `COND_REVENUE` |
| 종사자 수 | 종사자수 | `COND_HEADCOUNT` |
| 기업규모 | 없음 | `COND_COMPANY_TYPE` |
| 인증 여부 | 인증 | `COND_CERTIFICATION` |
| 기타 조건 | 기타 | `COND_OTHER` |
| 제외조건 | 제외 | `COND_EXCLUSION` |

명시적 하위 라벨이 있으면 그 라벨이 occurrence의 축을 결정한다. 값의 단어를
보고 다른 축으로 바꾸지 않는다.

## 4. 라벨 값 범위

알려진 라벨의 값 범위는 라벨 구분자 직후부터 다음 중 먼저 오는 위치 직전까지다.

1. 같은 줄의 다음 알려진 라벨
2. 현재 줄의 끝

따라서 occurrence는 다음 줄로 넘어가지 않는다. 다음 줄이 알 수 없는 하위
라벨이더라도 앞 occurrence에 포함하지 않는다. 알 수 없는 라벨은 새 축을
생성하지 않으며, 이 문법의 Rule occurrence로도 만들지 않는다.

값 앞뒤의 공백과 구분용 쉼표·가운데점은 occurrence 원문에서 제외한다. 빈 값은
축 occurrence를 만들지 않는다.

## 5. 정량 조건 정규화

업력·매출액·종사자 수는 명시적 라벨로 축을 정한 뒤 기존 정량 정규화 규칙을
적용한다. 정규화가 성립하지 않아도 라벨이 지배하는 원문과 축은 보존하고,
원문에 없는 값을 생성하지 않는다.

종사자 수의 경계값 단위는 `명`과 `인`을 모두 `PERSON`으로 정규화한다.

```text
종사자 수: 10명 이하  -> unit=PERSON
종사자 수: 10인 이하  -> unit=PERSON
상시 근로자 10인 이하 -> unit=PERSON
```

단, 명시적 `종사자 수`/`종사자수` 라벨이나 `근로자`/`종사자` 문맥이 없는
`숫자+인`은 인원 조건으로 추론하지 않는다.

```text
기타 조건: 10인 이하  -> COND_HEADCOUNT로 추론하지 않음
```

## 6. 수용 조건

- 알 수 없는 다음 줄 하위 라벨이 앞의 알려진 라벨 occurrence에 섞이지 않는다.
- `지역: 대전광역시, 업종: 제조업`은 한 줄에서 두 occurrence로 분리된다.
- 업력·매출액·종사자 수가 §11.2 라벨 축 표의 정식 항목으로 동작한다.
- 종사자 수의 `명`과 `인`은 `PERSON`으로 정규화된다.
- 라벨이나 사람 문맥이 없는 `숫자+인`은 `COND_HEADCOUNT`를 만들지 않는다.
- 기존 미커밋 Rule/LLM occurrence 좌표·중복 제거 변경은 보존한다.

## 7. 이번 버전에서 제외하는 범위

지원내용 범위, 보조율·자부담률, 측정시점, 에이전트 전문화는 이 문법과 구현
범위에 포함하지 않는다. API, DB, migration, CPL 필드 수와 확인율 계약도
변경하지 않는다.
