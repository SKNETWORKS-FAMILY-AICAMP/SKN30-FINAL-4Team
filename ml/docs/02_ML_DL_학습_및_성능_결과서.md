## 왜 이 모델들인가 — 한눈에

**두 과제 모두 베이스라인부터 전 후보를 같은 분할·같은 시드로 측정했습니다.** 어느 하나도 "보통 이걸 쓰니까"로 정하지 않았고, 지원성격 분류는 **교차검증 승자와 실제 적용 승자가 갈렸습니다** — 그래서 최종 판단은 실제 적용 쪽을 따랐습니다.

| 과제 | 후보 | 채택 | 결정적 근거 |
|---|---:|---|---|
| 지원성격 분류 | ML 2종 + DL 1종 (19클래스 재학습) | **LogisticRegression(ML)** | CV는 DL이 이겼지만(0.8337 vs 0.7953) 실제 Open API 적용에서 역전(51.2% vs 60.98%) |
| 지원규모 시계열 | 6종 | **없음** | 전 모델이 Last Value에 6배 뒤져 예측을 제공하지 않음 |

### 딥러닝은 교차검증에서만 이겼습니다

| 모델 | ML 기준선 (그룹CV) | 딥러닝 (그룹CV) | 실제 적용 (정답 41건) | 판정 |
|---|---:|---:|---:|---|
| 1. 지원성격 분류 | LogReg 0.7834 / LinearSVM 0.7953 | **KLUE-RoBERTa 0.8337** | **LogReg 60.98%** vs RoBERTa 51.2% | ✅ **ML 채택** |
| 지원규모 시계열 | 관측 기반 집계 | 시계열 92개월로 부족 | — | ❌ 미적용 |

**교차검증 성능이 배포 결정을 대신할 수 없었습니다.** RoBERTa 는 사전학습 한국어 지식으로 그룹CV 기준선을 확실히 넘었지만, 그 성능이 실제 공고문(다른 원천·다른 문체·다른 연도)에 그대로 옮겨가지 않았습니다. 뒤에서(2.6절) 원인을 확신도 보정 붕괴로 특정합니다.

## 1. 검증 설계

### 1.1 모델별 분할 방식

| | 모델 1 분류 (현재) | 지원규모 시계열 |
|---|---|---|
| **방식** | **StratifiedGroupKFold** (5-fold, 그룹=`program_stem`) | **Walk-forward** 2-Fold |
| **분할 단위** | 행 (층 = 클래스, 그룹 = 사업) | 시간 |
| **데이터** | 1,404행 / 19클래스 / 1,203그룹 | 92개월 |
| **train : val** | 대략 80 : 20 (그룹 단위라 가변) | 83~90 : 10~17 (가변) |
| **K-Fold 교차검증인가** | ✅ (그룹 통제) | ❌ |

모델 1은 2022+2023 두 해 엑셀을 병합하면서 데이터가 900행(2023 단독·26클래스)에서
1,404행(19클래스)으로 늘었습니다. 같은 사업이 두 해에 걸쳐 재공고되는 사례가
`program_stem` 기준 215그룹이라, **일반 Stratified K-Fold 를 쓰면 같은 사업이**
**학습/검증에 갈라져 성능이 부풀려집니다**(1.3절 실측).

### 1.2 fold별 실제 행수

**모델 1 — StratifiedGroupKFold (1,404행 / 19클래스 / 1,203그룹, 5-fold)**

그룹 단위 분할이라 fold별 정확히 80:20 이 나오지 않습니다. 1,404행 전부가
검증에 정확히 1회씩 쓰이는 것은 K-Fold 이므로 그대로 유지됩니다.

**지원규모 시계열 — Walk-forward 2-Fold**는 3장에서 다룹니다. K-Fold가 아니라
walk-forward인 이유는 — 시계열에서 K-Fold를 쓰면 미래 데이터로 과거를 맞히는
시간 누수가 생기기 때문입니다.

### 1.3 fold 내부에서 통제한 누수

**fold 밖에서 미리 계산하면 안 되는 것들**입니다.

| 대상 | 잘못된 방식 | 적용한 방식 |
|---|---|---|
| TF-IDF 어휘 | 전체 데이터에 fit | **Pipeline으로 fold train에만 fit** |
| TruncatedSVD | 전체에 fit | fold train에만 fit |
| StandardScaler | 전체에 fit | fold train에만 fit |
| 결측 대치값(중앙값) | 전체 중앙값 | **fold train의 중앙값** |
| lag·rolling 피처 | 전체 시리즈에 rolling | **shift(1) 이후 계산** |
| 분야별 중앙값 베이스라인 | 전체 중앙값 | fold train에서 산출 |
| **같은 사업의 재공고** | 일반 K-Fold (행 단위) | **그룹 K-Fold** (`program_stem` 단위) |

마지막 행이 2022+2023 병합 이후 새로 생긴 통제입니다. 실측 영향은 아래와 같습니다.

| 타깃 | 모델 | 일반 CV | 그룹 CV | 누수분 |
|---|---|---:|---:|---:|
| 지원성격(19클래스) | LogisticRegression | 0.7938 | 0.7834 | **−0.0104** |
| 지원성격(19클래스) | LinearSVM | 0.8200 | 0.7953 | **−0.0247** |

병합 전(2023 단독·14클래스, 재공고 그룹이 3건뿐)에서는 누수분이 거의 없었습니다
(LinearSVM 0.7037 → 0.6942, −0.0095). **병합으로 재공고 그룹이 늘면서 통제가**
**중요해졌습니다.**

### 1.4 딥러닝 단계의 추가 통제

| 대상 | 통제 |
|---|---|
| fold 분할 | ML과 **동일한 StratifiedGroupKFold** (`program_stem`) — 안 그러면 ML 때 잡은 누수를 DL에서 재현 |
| Early stopping 정지 시점 | **nested split** — outer train을 다시 쪼개 inner val로만 판단 (26클래스 시절 실험, 2.5절) |
| MC Dropout 불확실성 | **OOF 예측만 사용** (26클래스 시절 실험, 2.5절) |

### 1.5 알려진 제약

- **고정 holdout 이 없습니다.** 데이터가 1,404행으로 여전히 작아 전량을 교차검증에 씁니다. 대신 Open API 정답 41건(M07)이 사실상의 독립 holdout 역할을 했고, 여기서 CV 순위가 뒤집혔습니다.
- 클래스당 최소 표본이 MIN_SUPPORT=10 이라 여전히 얇은 클래스가 있습니다.

## 2. 모델 1 — 지원성격 분류

**채택: TF-IDF + LogisticRegression (그룹CV macroF1 0.7834, 판단보류 포함 실적용 60.98~79.31%)**

공고문을 읽고 지원성격 19클래스 중 하나로 분류합니다. 데이터가 두 단계를 거쳤습니다.

```text
2023 단독 · 26클래스 · 900건   (2.5절 — 이전 실험, ablation·early stopping·불확실성 분해)
        ↓ 2022 엑셀 병합
2022+2023 · 19클래스 · 1,404건 (2.1~2.4절 — 현재 채택 기준)
```

### 2.1 ML 벤치마크 (현재 채택 데이터)

같은 그룹CV·같은 seed 42로 쟀습니다.

| 모델 | 일반 CV (참고용) | **그룹 CV (정직한 기준선)** |
|---|---:|---:|
| **LinearSVM** | 0.8200 | **0.7953** |
| LogisticRegression | 0.7938 | 0.7834 |

**LinearSVM이 그룹CV에서 더 높지만 채택은 LogisticRegression 입니다.** 배포
파이프라인(`m02_apply.py`)이 `predict_proba` 로 확신도를 내야 판단보류
임계값(0.20/0.35)을 적용할 수 있는데, LinearSVM은 확률 출력이 없습니다.
0.0119 차이보다 판단보류 기능이 실무에 더 중요하다고 판단했습니다.

### 2.2 LinearSVM 을 보정해서 다시 겨뤄봤습니다 (M24)

위 결정은 "성능이 아니라 인터페이스 때문에 진 것"이라 되돌릴 여지가 있어
보였습니다. `CalibratedClassifierCV` 로 `decision_function` 을 확률로 바꾸면
판단보류를 걸 수 있습니다.

**임계값 숫자를 직접 비교하면 안 됩니다.** 모델마다 확률 분포가 달라 같은
0.6 이 서로 다른 커버리지를 뜻합니다. 확신도 상위 N% 를 남기는 방식으로
커버리지를 맞춘 뒤 정확도를 비교했습니다.

| 모델 | 커버리지 70.7% 고정 시 정확도 | 그때의 임계값 | macroF1 (전체) | ECE |
|---|---:|---:|---:|---:|
| **LogisticRegression (현행)** | **0.9215** | 0.347 | 0.7834 | 0.3455 |
| LinearSVM + sigmoid | 0.9164 | 0.636 | 0.7293 | 0.1081 |
| LinearSVM + isotonic | 0.8912 | 0.716 | 0.7190 | **0.0146** |
| LogisticRegression + isotonic | 0.8862 | — | — | 0.0660 |

**가설이 깨졌습니다.** 보정한 SVM 이 같은 커버리지에서 LR 을 넘지 못했습니다.
원인은 **보정 비용**입니다 — 보정기를 학습시키려면 학습 데이터의 30% 를
떼어내야 하고, 그만큼 분류기가 덜 배웁니다. 무보정 LinearSVM 0.7953 이
보정 후 0.7293 으로 떨어진 것이 그 대가입니다.

> **누수 통제** — `CalibratedClassifierCV(cv=k)` 를 그냥 쓰면 내부 분할이
> `program_stem` 그룹을 모릅니다. 같은 사업의 재공고가 학습부와 보정부로
> 갈라지면 보정기가 "이미 본 사업"으로 확률을 맞춰 낙관적으로 휩니다 —
> 1.3절이 잡았던 누수와 같은 종류입니다. outer fold 안에서 그룹 단위로 다시
> 쪼개 `FrozenEstimator` 로 붙였습니다.

#### 대신 다른 것을 확인했습니다 — LR 의 확신도는 확률이 아닙니다

| | 평균 확신도 | 실제 정확도 | ECE |
|---|---:|---:|---:|
| **LogisticRegression (현행)** | **0.4828** | **0.8283** | **0.3455** |

**평균 확신 0.48 인데 실제로는 0.83 을 맞춥니다.** 심하게 과소확신입니다.
임계값 0.20/0.35 가 경험적으로 작동하는 것과는 별개로, **이 숫자를 사용자에게
"확신도 48%"로 보여줄 수는 없습니다.** 확률로서 의미가 없기 때문입니다.

같은 LR 을 isotonic 보정하면 ECE 가 0.3455 → 0.0660 으로 잡히지만, 같은
커버리지 정확도는 −0.0353 입니다. **분류기 성능과 확신도 표기는 맞바꿔야
하는 관계**라는 뜻입니다.

| 용도 | 선택 |
|---|---|
| 내부 판단보류(임계값만 쓰고 숫자는 안 보여줌) | 현행 LR 그대로 |
| 화면에 "확신도 N%" 표기 | isotonic 보정 필요 (정확도 −0.035 감수) |

#### 클래스별 임계값 차등

어느 클래스가 혼동이 심한지 **데이터로 정했습니다** — 그 클래스로 예측했을
때의 정확도가 낮은 순 상위 3개(LR 기준 SW·솔루션 / 성능인증 / 창업보육).

| 방식 | 커버리지 | 정확도 |
|---|---:|---:|
| 일괄 0.50 | 41.3% | 0.9672 |
| 차등 (약한 클래스만 0.70) | 40.0% | **0.9769** |

커버리지를 1.3%p 만 내주고 정확도를 +0.0097 올립니다. 작지만 방향은 맞습니다.

### 2.3 TF-IDF feature 고도화 — 현행이 이미 최적입니다 (M25)

char n-gram 범위·어휘 크기·정규화 강도·벡터라이저 조합·필드별 분리를 전부
훑었습니다(그룹CV, one-factor-at-a-time).

| 축 | 값별 macroF1 | 최적 |
|---|---|---|
| ngram | (2,4) **0.7834** / (2,5) 0.7804 / (3,5) 0.7668 / (2,6) 0.7764 | (2,4) 현행 |
| max_features | 60k / 100k / 150k 전부 **0.7834** | 차이 없음 |
| C | 0.5 0.7065 / 1.0 0.7522 / 2.0 0.7724 / 3.0 0.7807 / **5.0 0.7834** | 5.0 현행 |
| vectorizer | char **0.7834** / char+word 0.7735 / word 0.7255 | char 현행 |
| field-wise | **0.7281** (−0.0553) | 현행이 나음 |

**어느 축도 현행을 넘지 못했습니다.**

- `max_features` 를 60k → 150k 로 늘려도 값이 그대로입니다. `min_df=2` 문턱에서 이미 걸러져 60k 를 다 못 채운다는 뜻입니다.
- **필드별 분리 벡터화가 오히려 나빠집니다**(−0.0553). 필드마다 어휘를 따로 만들면 `max_features` 가 1/4 로 쪼개지고 `min_df=2` 를 못 넘는 항이 늘어납니다. "제목의 '융자'와 본문의 '융자'를 구분한다"는 이득보다 어휘가 얇아지는 손해가 큽니다.

### 2.4 딥러닝 재학습 — 그룹CV에서는 이겼습니다

같은 1,404행·19클래스·같은 그룹CV로 KLUE-RoBERTa 를 다시 학습시켰습니다.

| 모델 | 그룹CV macroF1 | ML 기준선 대비 |
|---|---:|---:|
| ML 최고 (LinearSVM) | 0.7953 | — |
| KLUE-RoBERTa (기준 설정) | 0.8283 | +0.0330 |
| **KLUE-RoBERTa (ablation 최적조합)** | **0.8337** | **+0.0384** |

**Ablation — one-factor-at-a-time** (기준 설정에서 축 하나씩만 변경, 5-fold)

| 축 | 값 | macroF1 | 비고 |
|---|---|---:|---|
| lr | 1e-5 / 2e-5 / **3e-5(기준)** / 5e-5 | 0.7956 / 0.8209 / 0.8283 / **0.8364** | 5e-5가 최적 |
| epochs | 5 / **8(기준)** / 12 | 0.8144 / 0.8283 / 0.8151 | 8이 정점, 12는 과적합 |
| batch | 8 / **16(기준)** / 32 | 0.8322 / 0.8283 / 0.8249 | 작을수록 근소 우위 |
| max_len | 128 / **256(기준)** / 384 | 0.8268 / 0.8283 / 0.8305 | 384가 근소 우위 |
| class_weight | **True(기준)** / False | 0.8283 / 0.8158 | 끄면 −0.0125 |
| fields | title / title+목적 / title+목적+내용 / **all(기준)** | 0.6785 / 0.7312 / 0.8172 / 0.8283 | 입력 필드가 하이퍼파라미터보다 영향이 큼 |

최적조합(`lr=5e-5, epochs=8, batch=8, max_len=384, class_weight=True, fields=all`)
→ macroF1 **0.8337**. 학습 3,659초(약 61분, GPU).

> 이 값은 하이퍼파라미터 선택에 쓰인 CV 성능이라 그대로 일반화 성능으로 제시하면
> 안 됩니다 — 편향 없는 평가는 2.4절의 Open API 정답 41건 대조입니다.

같은 41건에 ML(LogisticRegression, 판단보류 포함)과 DL(RoBERTa, 2.2절 최적조합)을

| 모델 | 범위 | 정확도 | 커버리지 |

**원인은 확신도 보정 붕괴입니다.** RoBERTa 의 확신도 구간별 실제 정확도입니다.

| 확신도 구간 | n | 평균 확신도 | 실제 정확도 | 과신 |
|---|---:|---:|---:|---:|
| 0.50~0.70 | 2 | 0.689 | 0.000 | +0.689 |
| 0.70~0.90 | 2 | 0.839 | 0.500 | +0.339 |

오분류는 인접 클래스 혼동이 많았습니다 — 판로→해외수주·실증/컨설팅, 융자→보증/컨설팅,
기술·IP평가→사업화 등. 평균 확신도는 0.9230 으로 전체적으로 매우 높았습니다.

**방법론적 결론은 유효합니다.** 최종 채택 근거로는 쓰지 않습니다.

## 3. 지원규모 시계열 — 왜 예측 모델을 두지 않는가

**채택: 없음 — 예측 대신 관측 기반 참고범위를 제공합니다.**

공고문 원문에서 지원규모를 추출해 **분야·시기별 지원규모 추이**를 파악합니다. 단일 예측 모델이 아니라 정보추출 → 집계 → 시계열 분석 파이프라인입니다.

```
공고문 원문(HWP 계열) → 지원규모 추출 → 의미 유형별 정규화
                     → 월 × 대분류 × 금액의미 집계 → 시계열 → STL → 조건부 예측
```

> **PDF 원문은 제외했습니다.** `pdf-inspector`가 표의 여러 행을 한 셀로 뭉쳐
> 금액을 왜곡합니다 — 표 보유 PDF의 **13.6%**에서 한 셀에 금액 3개 이상이 병합됐고
> (HWP는 **0%**), 해당 문서 기반 `per_company`는 중앙값 2배·p95 3.8배로 부풀려졌습니다.
> 예: `238만원 | 119만원 | 476만원 | 1,900만원` 4개 행이 한 셀로 뭉쳐 **39억원**으로 파싱.
> 병합 탐지 규칙으로 일부만 거르는 대신, 오류가 0인 HWP 계열만 사용합니다.
> 관측은 3,786 → **2,458건**으로 줄지만 신뢰도를 택했습니다.
> 원문 병합 단계(`f04`)에도 같은 기준을 적용해, 병합본에 PDF 금액이 남아
> 요약문 폴백 경로로 되돌아오던 문제까지 막았습니다.

### 왜 예측 모델을 채택하지 않았는가

**예측은 조건을 충족할 때만 제공합니다.** 지원규모는 공고량보다 데이터 품질 요구가 높아, 5개 조건을 순서대로 판정했습니다.

| 조건 | 내용 | `per_company` | 나머지 3종 |
|---|---|:---:|:---:|
| 1 | 관측치가 충분할 것 | ✅ 807건 | ✅ |
| 2 | 같은 의미끼리 집계될 것 | ✅ | ✅ |
| 3 | 월별 결측이 과도하지 않을 것 | ✅ 10.9% | `per_project` 39.1% ❌ |
| **4** | **STL/ACF에서 시간 구조가 확인될 것** | **❌ 계절성 0.000** | **❌ 탈락** |
| 5 | walk-forward에서 baseline 개선 | — | — |

**4종 전부 조건 4에서 탈락합니다.** 참고로 조건 4를 무시하고 `per_company`에 예측을 강행해도 결과는 같습니다.

지원규모는 이상치가 강해 **median**을 주 지표로, 자릿수 범위가 넓어 **log10 스케일**에서 분해했습니다.

> **데이터를 정리할수록 "구조"가 사라졌습니다.** `per_company`의 계절성 추이입니다.

## 5. 이 수치를 믿을 수 있는 이유

성능 수치만으로는 누수를 알 수 없습니다. 전처리 단계에서 **라벨 누수 2종과 시간 누수 1종**, 그리고 **재공고 그룹 누수 1종**을 찾아 차단했고, 그 영향을 실측했습니다.

**차단하지 않았다면 이런 표를 보고할 뻔했습니다**

| 타깃 | 모델 | 누수 포함 | 누수 제거 | 차이 |
|---|---|---:|---:|---:|
| 중분류 | LinearSVM | 0.7762 | 0.5129 | **−0.2633** |
| 업종 | LinearSVM | 0.8721 | 0.7030 | **−0.1691** |
| 지원성격(19클래스, 재공고 그룹) | LinearSVM | 0.8200 | 0.7953 | **−0.0247** |
| 지원성격(19클래스, 재공고 그룹) | LogisticRegression | 0.7938 | 0.7834 | **−0.0104** |

2023 엑셀의 `사업개요` 첫 줄에 정답이 그대로 있었습니다(대분류 노출률 100%, 중분류 99.9%). Open API `hashtags`의 첫 토큰도 분야 라벨과 동일했습니다(100%). 2022+2023 병합 이후로는 **같은 사업이 두 해에 재공고되는 사례**(215그룹)가 새로운 누수 경로였습니다.

**네 가지 검증 장치**

**① fold 내부 fitting** — TF-IDF·SVD·Scaler·결측 대치값을 모두 fold train에만 적합시킵니다. 전체 데이터에 미리 fit하면 검증 fold의 정보가 전처리기를 통해 새어 들어갑니다.

**② 그룹 K-Fold** — 같은 사업(`program_stem`)이 학습과 검증에 동시에 들어가면 안 됩니다. ML·DL 모두 StratifiedGroupKFold 로 통제했습니다.

**③ shift(1) 이후 rolling** — 시점 t의 피처는 t−1 이전 정보만 담습니다. 전체 시리즈에 rolling을 걸고 나중에 자르면 2022년 검증 샘플의 피처에 2023년 값이 들어갑니다.

```python
prev = y.shift(1)                     # 당월 값이 자기 피처에 들어가지 않게
for w in (3, 6, 12):
    df[f"rolling_mean_{w}"] = prev.rolling(w, min_periods=w).mean()
```

**④ 독립 정답셋 대조** — 그룹CV만으로 배포를 결정하지 않았습니다. Open API 정답 41건(M07)이라는, 학습·검증 어느 fold에도 없던 표본으로 최종 재확인했고, 여기서 실제로 CV 순위가 뒤집혔습니다.

**모델 비교의 공정성** — ML과 DL을 같은 StratifiedGroupKFold, 같은 seed 42, 같은 입력 필드로 측정했습니다.

## 6. 결론

1. **누수를 통제하지 않으면 성능표가 무의미합니다.** 라벨 누수만으로 Macro F1이 0.17~0.26 부풀려졌고, 재공고 그룹 누수도 최대 0.025 부풀렸습니다.

2. **교차검증에서 이긴 모델이 배포 승자가 아닐 수 있습니다.** KLUE-RoBERTa는 그룹CV에서 ML을 +0.038 앞섰지만, 독립 정답셋(Open API 41건)에서는 60.98% vs 51.2%로 역전당했습니다. **CV 성능은 배포 결정의 최종 근거가 아니라 후보를 좁히는 1차 필터**입니다.

3. **확신도가 높다고 정확한 것이 아닙니다.** RoBERTa의 확신도 0.90~0.99 구간(17건)에서 실제 정확도는 11.8%였습니다. 판단보류 임계값을 걸어도 이 구간은 걸러지지 않습니다 — 확신도 자체가 신뢰할 수 없는 신호였습니다.

4. **성능이 좋아도 실효성이 없으면 채택하지 않았습니다.** 공고량 예측 모델은 베이스라인 대비 개선이 paired 검정으로 확립됐지만, 부처가 실제로 조정 근거로 쓸 유인·권한이 약하다고 판단해 제외했습니다.

5. **딥러닝이 데이터 규모로 이기는 것과 도메인에서 이기는 것은 다른 질문입니다.** 900건이든 1,404건이든 사전학습 지식으로 그룹CV는 넘었지만, 학습 데이터(2022~2023 중앙부처 엑셀)와 적용 대상(2026 Open API 원문)의 문체·연도 차이 앞에서는 흔들렸습니다.

6. **하이퍼파라미터보다 입력 구성이 중요합니다.** 19클래스 재학습에서도 입력 필드 영향폭(title→all: +0.15)이 lr·epochs·batch·max_len을 모두 앞섰습니다.

7. **`predict_proba` 유무가 최고 성능 모델보다 중요할 수 있습니다.** LinearSVM이 그룹CV에서 0.0119 더 높았지만, 확률 출력이 없어 판단보류 임계값을 걸 수 없다는 이유로 LogisticRegression을 채택했습니다. **보정으로 이 제약을 풀어봤지만 되돌리지 못했습니다**(2.2절) — 보정기 학습에 데이터의 30%를 떼는 비용이 그 이상이었습니다.

8. **채택한 모델의 확신도도 확률이 아닐 수 있습니다.** LR은 평균 확신 0.48로 실제 정확도 0.83을 맞춥니다(ECE 0.3455, 과소확신). 임계값이 경험적으로 작동하는 것과, 그 숫자를 사용자에게 보여줄 수 있는 것은 다른 문제입니다.

9. **튜닝 여지가 없다는 것도 측정 결과입니다.** TF-IDF의 5개 축을 전부 훑어 어느 것도 현행을 넘지 못했습니다(2.3절). 이건 실패가 아니라 "여기는 더 팔 곳이 없으니 다른 데를 보라"는 정보입니다.

8. **파싱 오류가 없는 구조를 만들어내기도 합니다.** PDF 표의 셀 병합을 걷어내자 `per_company`의 계절성이 0.441 → 0.118로 떨어져 조건 4를 통과하던 유일한 유형이 탈락했습니다.

## 7. 남아 있는 한계

**1. 고정 홀드아웃이 없습니다**
전량을 교차검증에 씁니다. Open API 정답 41건(M07)이 사실상 독립 평가 역할을 했지만, 정식 holdout 분리는 아닙니다.

**2. RoBERTa의 확신도를 어디에도 쓸 수 없게 됐습니다**
2.6절에서 확인했듯 0.90~0.99 구간 실제 정확도가 11.8%입니다. 판단보류·신뢰등급 어느 용도로도 이 모델의 자체 확신도를 신뢰할 수 없습니다. 재보정(temperature scaling 등)을 시도하지 않았습니다.

**3. 정답 41건은 여전히 작습니다**
CV 순위를 뒤집을 만큼 결정적이었지만 41건입니다. 표본을 100~200건으로 늘리면 결론이 더 굳어질지, 흔들릴지 아직 모릅니다.

**4. 꼬리 클래스는 여전히 얇습니다**
MIN_SUPPORT=10 필터를 걸었지만 19클래스 중 다수가 경계선입니다.

**5. 지원규모 시계열의 대표성 차이**
2019~2025(층화 표본)와 2026(Open API)의 수집 설계가 다릅니다. 연도 간 직접 비교가 불가능하며, "관측된 공고의 지원규모 추이"로만 해석해야 합니다.

**6. 지원규모 시계열의 학습 데이터가 92개월입니다**
피처가 15개라 학습 구간 대비 과다합니다. ML 모델이 Last Value baseline에 크게 뒤진 직접적 원인이며, 딥러닝을 적용하지 않은 이유이기도 합니다.

**7. `unknown` 940건이 타깃에서 빠졌습니다**
전체 관측의 34.7%입니다. 금액은 뽑혔지만 "기업당인지 총사업비인지"가 미확정이라 집계에 넣을 수 없습니다.

**8. PDF 원문을 통째로 버렸습니다**
표 셀 병합 때문에 PDF 전체를 제외했지만, 병합이 없는 PDF도 상당수입니다. 병합 탐지 규칙을 신뢰할 수 있게 다듬거나 PDF 표 추출기를 교체하면 관측을 되찾을 수 있습니다. 현재는 안전한 쪽을 택했습니다.

### 다음 단계

- **RoBERTa 확신도 재보정 또는 폐기** (한계 2) — temperature scaling 을 시도하거나, 안 되면 이 모델의 확신도 출력 자체를 쓰지 않는다
- **Open API 정답셋 확대 100~200건** (한계 3) — 우선순위 최상. CV 역전이 표본이 커져도 유지되는지 확인
- 19클래스 체계 안에서도 꼬리 클래스 병합 재검토 (한계 4)
- `unknown` 940건의 의미 확정 (한계 7) — 관측치 35% 증가 여지
- PDF 표 추출 개선 (한계 8) — 제외한 PDF 관측 복구
