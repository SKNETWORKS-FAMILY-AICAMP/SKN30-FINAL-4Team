## 6. 옮기지 **않은** 것과 그 이유

### `ml/reports/` 는 평면으로 둡니다

역할별로 쪼개면 **107개 호출부가 깨집니다.** 스크립트들이 서로의 리포트를
경로로 직접 읽습니다 — `dl13` 이 `m30` 의 json 을, `dl17` 이 `m36` 의 것을,
`dl15` 는 12개 리포트를 모아 읽습니다. 나누면 이 교차 참조가 전부 끊깁니다.

대신 어느 리포트가 누구 것이고 채택/기각이 어떻게 됐는지를
`evaluation/RESULTS.md` 와 `experiments/RESULTS.md` 가 색인합니다.

### 실험 스크립트 49개를 지우지 않습니다

용량 문제가 아니었습니다 — `ml/scripts/` 전체가 1.5 MB 였고, 저장소를 무겁게
한 것은 `.git` 의 도달 불가 객체였습니다. 그리고 **M58~M61 같은 기각 기록이
"모델 3 모델링을 종료한다"는 결론의 근거**입니다. 지우면 그 근거가 사라집니다.

### `pipelines/` 에 실험처럼 보이는 것이 섞여 있습니다

`m33`·`m34`·`m36`·`m37`·`m41`·`m43` 은 그 자체로는 탐색이었지만 **채택 경로가
import 하고 있습니다.** 의존 방향(상류 → 하류)을 지키려면 여기가 맞습니다.
역방향 의존은 `dl11_m1_export`(pipelines) → `m29_m1_external_eval`(evaluation)
**1건뿐**이고, 외부 검증셋 구성 코드가 평가 스크립트 안에 있어 생긴 것입니다.

## 7. 구조를 옮기면서 지켜야 하는 두 가지

**1. 스크립트는 `ml/` 바로 아래 한 단계에만 둡니다.**
`common.ROOT` 가 `dirname(dirname(__file__))` 로 계산됩니다. 두 단계 아래로
내리면 `ROOT` 가 `ml/` 이 아니게 되고 데이터 경로가 전부 어긋납니다.

**2. 스크립트끼리 평면 이름으로 import 합니다.**
`import common as C`, `from m13_m4_anomaly import prepare` 같은 식이라 폴더를
나누면 그대로는 깨집니다. 각 파일 맨 위에 세 디렉터리를 `sys.path` 에 얹는
bootstrap 블록을 넣었습니다(deep-learning 85개 파일). 95개 모듈 전부 새
위치에서 import 되는 것을 확인했습니다.
