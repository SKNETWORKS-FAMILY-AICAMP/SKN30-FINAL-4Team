# M66 — 얇은 비교군을 먼저 채우고 현행 모델 3 을 재평가

> 지시 Model 3: `MIN_COHORT=20` 근처의 얇은 비교군을 **이미 가진 문서에서**
> 더 뽑아 보강하고, 비교군 축 결측을 줄인 뒤, **현행 구조 그대로** 재평가한다.

바뀐 것은 입력 데이터 하나뿐입니다. 거리 기반 이례성 점수 · 비교군 사다리
(성격x방식) · mean 대표벡터 · standard scaling · Euclidean · `MIN_COHORT=20`
전부 M44 Freeze 그대로입니다.

| 대상 | n | 전역 fallback | 재표집 ρ(0.8) | Top30(0.8) | 방향 일관성 | attribution |
|---|---:|---:|---:|---:|---:|---:|
| A v2 pool (현행) | 2451 | 57 (2.33%) | 0.965 | 0.747 | 1.00 | 0.957 |
| B 교집합 · v2 | 2451 | 57 (2.33%) | 0.965 | 0.747 | 1.00 | 0.957 |
| **B 교집합 · v3** | 2451 | 57 (2.33%) | 0.962 | **0.682** | 1.00 | 0.947 |
| **C v3 pool (보강 후 운영상태)** | 2626 | 61 (2.32%) | **0.967** | 0.738 | 1.00 | **0.970** |

`design_features_v2.parquet` 는 얼려 둡니다. `--supply` 없이 F06 을 다시 돌리면
sha256 `eced88f6767e2e24` 가 그대로 나옵니다 — **모델 2 의 canonical 입력은**
**한 바이트도 안 바뀌었습니다.**

## 1. 무엇을 더 뽑았는가

새 문서를 받지 않았습니다. E01 이 이미 뽑아 두고 M65 가 이미 근거문으로 붙여 둔
그 텍스트만 다시 읽습니다. 세 가지이고, 순서가 곧 의존관계입니다.

| | 무엇 | 규모 (전체 3,963행 기준) |
|---|---|---:|
| **S1** | `support_unit` — `20개사 내외` 처럼 **개수 표현 자체**가 단위를 말하는 자리 | 109행 |
| **S2** | S1 이 만든 문서근거 단위로 `amount_type` 의 `unknown` 해소 | 274행 |
| **S3** | 금액 문맥·지원규모 절에서 `support_ratio` ('무엇의 몇 %') | 323행 |

**채우기만 합니다.** 이미 값이 있는 칸은 건드리지 않았습니다. 교집합 2,451행에서
실측하면 이렇습니다 — **잃은 칸이 0** 이라는 줄이 이 규율의 증거입니다.

| 축 | 채움 | 잃음 | 결측률 |
|---|---:|---:|---|
| `support_unit` | 85 | 0 | 16.2% → **12.7%** |
| `support_ratio` | 215 | 0 | 61.9% → **53.1%** |
| `log_per_recipient` | 156 | 0 | 22.8% → **16.4%** |
| `log_support_count` | 0 | 0 | 19.5% → 19.5% |
| `project_duration` | 0 | 0 | 35.5% → 35.5% |

> `C v3 pool` 열에서 `log_support_count`·`project_duration` 결측률이 올라가
> 보이는 것은 **분모가 달라졌기 때문**입니다(M64 가 같은 것을 설명했습니다).
> 위 표는 같은 행에서만 읽은 것이고, 거기서는 0/0 입니다.

### S1 과 S2 는 어휘를 새로 만들지 않습니다

S1 이 읽는 것은 `amount_parser.COUNT_RE` 가 **이미 `support_count` 를 뽑을 때**
**쓴 그 매치**입니다. 그 표현이 무엇을 세었는지(`개사`/`개 과제`/`개 팀`)만
읽으므로, 뽑힌 개수와 그 개수의 단위가 정의상 어긋날 수 없습니다. 맨 `개` 는
무엇의 개수인지 알 수 없어 단위로 쓰지 않습니다.

S2 는 taxonomy 에서 `resolve_amount_type` 이 **코호트 관행**으로 하던 일을
bizinfo 에서 **문서 근거**로 합니다. 관행으로 되돌린 단위
(`amount_type_convention`)는 쓰지 않습니다 — 그것으로 `amount_type` 을 정하면
순환입니다. 새로 생긴 기업당 지원액 256건은 기존 분포 안에 들어옵니다
(log10 중앙값 7.00 vs 기존 7.70)이고 **금액 파싱오류 플래그는 0건**입니다.

### S3 의 방향은 지배어가 정합니다

'총사업비의 25%' 와 '민간부담금 25%' 는 같은 숫자지만 지원비율은 75% 와 25% 로
반대입니다. 그래서 비용어·지원어가 조사 `의` 로 % 를 **직접 지배**할 때만
인정하고, 매치 바로 뒤에 부담 표현이 붙으면 뒤집습니다. 문장 어딘가에 비용어가
있기만 하면 잡는 방식으로는 **문서 길이가 비율을 정하게** 됩니다(M62 D2 가
지원단위에서 같은 실패를 막은 규율).

> 근거등급별 표본 156건을 근거창과 함께 `m66_m3_supply_audit.csv` 로 남깁니다.
> 규칙으로 채운 값은 '맞는 값'이 아니라 **'뽑힌 값'**입니다.

## 2. 얇은 비교군은 얼마나 찼는가 — **12칸 중 2칸** (목표 6칸)

칸 목록은 **v2 기준으로 고정**했습니다. 보강 후에 다시 고르면 '늘어난 칸만
골랐다'가 됩니다. 그리고 보강은 **문서가 있는 행 전체에 균일하게** 적용했습니다 —
얇은 칸에만 적용하면 '보강했더니 그 칸이 커졌다'가 동어반복이 됩니다.

| 비교군 | v2 | v3 | |
|---|---:|---:|---|
| `판로 x service` | 15 | **30** | 20 도달 |
| `판로 x other` | 13 | **22** | 20 도달 |
| `사업화 x guarantee` | 14 | 19 | |
| `컨설팅 x mixed` | 10 | 18 | |
| `창업보육 x grant` | 16 | 17 | |
| `연구개발 x other` | 16 | 17 | |
| `SW·솔루션 x grant` | 17 | 17 | |
| `수출물류 x grant` | 12 | 14 | |
| `판로 x mixed` | 10 | 14 | |
| `컨설팅 x loan` | 14 | 14 | |
| `교육훈련 x service` | 11 | 13 | |
| `판로 x voucher` | 12 | 13 | |

**지시가 잡은 6칸에 못 미칩니다. 왜 그런지가 이번 작업의 실질 결론입니다.**

6칸은 *그 12칸의 pool 밖 문서 보유 행 80건이 전부 회수된다면* 나오는 수입니다.
실제로 회수된 것은 48건이고, 12칸의 표본은 160 → 208 로 늘었습니다. 남은 202행의
정체를 세면 이렇습니다.

| 남은 pool 밖 행 | 수 | 회수 가능성 |
|---|---:|---|
| 문서가 아예 없음 (`scale_text`·`api_summary`) | 169 | 새 수집 필요 |
| 문서는 있으나 근거가 없음 | 33 | **소진** |

문서를 가진 33행은 30행이 단위 근거가 없고, 33행 전부 지원비율 근거가 없으며,
28행이 지원기업수 표현이 없습니다. **추출 개선으로 더 캘 것이 남아 있지**
**않습니다.** M64 가 "표본 확대의 절반은 추출 개선"이라고 했는데, 이번에 재보니
문턱 근처 12칸에서는 **그 절반이 48/250 = 19%** 였습니다. 나머지는 모델링이나
파싱이 아니라 **문서 수집** 문제입니다.

> 문턱 미달 칸의 행수 자체는 350 → 368 로 늘었습니다. 보강이 pool 을 넓히면서
> 아직 20 에 못 미치는 칸에도 행이 붙기 때문입니다. 비교군 사다리는 그대로라
> 이 행들은 L2(성격만)로 물러납니다.

## 5. B 의 Top30 이 왜 떨어지는가 — 결측 대치의 문제입니다

이 한 줄이 이번 작업에서 제일 중요합니다.

`build_vectors_v` 는 결측 수치축을 **train 중앙값으로 대치**합니다. 그러면
값이 없는 행은 그 축에서 **정확히 z=0**, 즉 '완벽하게 평균적'으로 채점됩니다.
v2 에서 `지원비율`이 결측이던 61.9% 는 지원비율이 평균이어서가 아니라
**값을 몰라서** 평균 자리에 놓여 있었습니다.

215행을 채우자 그 자리가 드러납니다.

| | |
|---|---|
| 대치값(중앙값) | 80.0% |
| 새로 채운 값의 실제 분포 | 중앙값 80.0% · 표준편차 25.1 · 최소 0 · 최대 100 |
| 중앙값에서 \|z\|>1 인 행 | 75 / 215 (**35%**) — 결측이었을 때는 전부 z=0 |

그래서 축을 채운 행의 점수는 중앙값 **+0.102** 오르고, 안 채운 행은 −0.002 로
제자리입니다. 실제로 v3 에서 새로 Top30 에 든 10건 중 **8건이 이번에 축을**
**채운 행**입니다 — pool 전체에서 축을 채운 행은 14.5% 뿐인데도 그렇습니다.

> **이것은 보강을 되돌릴 근거가 아닙니다.** 결측 대치 아래에서는 '모르는 값'이
> '평균적인 값'과 구별되지 않고, 그 상태의 Top30 안정성은 *모르는 것을 계속*
> *모르는 채로 두어서* 얻은 숫자입니다. M64 가 v1 의 Top30 0.827 을 두고
> "`grant` 한 덩어리로 뭉쳐 있어서 안정적이었던 숫자"라고 한 것과 같은 모양이고,
> **안정성과 정합성이 반대로 움직이는 자리**입니다.
>
> 그리고 pool 이 실제로 늘어난 운영상태(C)에서는 다섯 지표가 전부 유지되고
> Spearman·attribution 은 오히려 개선됩니다. 새 행 175건이 비교군을 굵게 만들어
> 대치가 드러낸 흔들림을 상쇄하기 때문입니다.

### 후속 후보 (이번에 손대지 않음)

1. **결측 수치축의 대치 방식.** 5절이 보여준 대로 지금은 '결측 = 평균'입니다.
   모델 4 의 `encode` 는 이미 결측 지시자 축을 함께 넣어 이 문제를 피하고
   있습니다(`f + "__missing"`). 모델 3 에 같은 것을 넣는 것은 **구조 변경**이라
   이번 범위 밖입니다. Mahalanobis 보다 먼저 볼 값어치가 있어 보입니다.
2. **문턱 근처 12칸의 문서 수집.** 169행이 문서 없이 남아 있습니다. 추출로는
   더 못 캅니다.
3. **Mahalanobis 유사 거리.** 양성 5건짜리 라벨셋으로는 지금도 가릴 수 없습니다.
