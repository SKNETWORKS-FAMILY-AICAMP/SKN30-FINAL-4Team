# M67 — 금액대 percentile 분기(2-stage) 실험

> 질문: **하나의 모델이 전체 금액 분포를 학습하는 것보다, 예상 금액대를
> 먼저 분류한 뒤 구간 전용 회귀 모델을 쓰는 것이 OOF 성능을 개선하는가?**

## 0. 같은 조건 / 바뀐 것

```text
dataset  data\processed\design_features_v2.parquet  (1877행)
sha256   eced88f6767e2e2460a05812dd8e9cd39990937e4c1a2a8363e02d114bfdc7f4
target   log10(per_recipient), basis=stated_cap
split    GroupKFold(5), group=program_stem / normalized_title
feature  m2-feat-v2 (구조화 + 제목 SVD64, fold 내부 적합)
바뀐 것  예측 경로만 — 단일 회귀 -> Stage1 분류 후 구간 전용 회귀
```

## 7. 누수 점검 / 재현성

| 점검 | 결과 |
|---|---|
| 경계 계산 입력 | fold train 의 y 만 (np.percentile(ytr, [33.3, 66.7])) |
| 경계가 fold 마다 흔들린다(전체 사전계산 아님) | True |
| fold별 경계(원) | [['20,000,000', '120,000,000'], ['20,000,000', '140,000,000'], ['20,000,000', '120,000,000'], ['20,000,000', '120,000,000'], ['20,000,000', '150,000,000']] |
| 전체데이터 경계(참고, 미사용) | ['20,000,000', '120,000,000'] |
| 전체 경계와 우연히 일치한 fold 수 | 3/5 — 타깃이 호가 단위에 뭉쳐 있어서 생기는 일치이지 누수가 아니다 |
| routing 입력 | predict_proba(Xte) 뿐 — yte 는 z_true(평가·oracle)에만 쓰인다 |
| Stage1 이 실제와 다른 구간으로 보낸 행 | 504 |
| 같은 seed 재실행 OOF 일치 | M65 단일 XGB True / 2-stage routed True / 2-stage oracle True / 2-stage soft True |
